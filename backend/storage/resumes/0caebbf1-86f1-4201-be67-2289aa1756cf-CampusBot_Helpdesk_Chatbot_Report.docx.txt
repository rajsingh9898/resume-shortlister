 INTRODUCTION TO PROJECT  
3.1 Project Background  
The rapid growth of digital helpdesk support has significantly increased the number of student queries received by organizations for every support ticket. Staff often spend considerable time manually reviewing student queries, comparing query details with FAQ criteria, and matching suitable FAQ matches. This manual screening process is not only time-consuming but also susceptible to human errors, inconsistencies, and unconscious bias. As organizations continue to receive hundreds or even thousands of queries, there is an increasing need for intelligent systems that can automate and optimize the query-resolution process.  
To address these challenges, CampusBot was developed as an AI-powered College Helpdesk Chatbot. The system leverages Artificial Intelligence (AI) and Natural Language Processing (NLP) techniques to analyze student queries, extract query details, compare student queries with FAQ answers, and rank queries based on their suitability. By combining semantic similarity, keyword matching, and confidence scoring, CampusBot provides students with accurate and instant recommendations, significantly reducing manual effort and improving response efficiency.  
The application enables students to submit their queries through various channels such as text chat, web form, and voice input, which are automatically parsed to identify the query intent, student roll number, department, and contact details. The extracted data is then evaluated against the FAQ entry using a hybrid AI model that combines Sentence Transformers for semantic matching and TF-IDF for keyword-based similarity scoring.  
In addition to intelligent query handling, CampusBot incorporates several enterprise-level features such as Role-Based Access Control (RBAC), secure JWT authentication, GDPRcompliant query data management, response-accuracy auditing, interactive analytics dashboards, and cloud database support. These features make the application suitable for modern student support environments where security, scalability, transparency, and compliance are essential.  
Overall, CampusBot demonstrates how Artificial Intelligence can transform traditional helpdesk support processes by enabling faster, more objective, and efficient response evaluation while supporting better response decisions.

3.2 Project Methodology  
The development of CampusBot – AI-Powered College Helpdesk Chatbot followed a structured Software Development Life Cycle (SDLC) approach. The project was implemented using an iterative development methodology, where each module was designed, developed, tested, and integrated systematically. This approach ensured that the application remained scalable, secure, and aligned with user requirements throughout the development process.  
The methodology consisted of six major phases: Requirement Analysis, System Design, Development, AI Model Integration, Testing, and Deployment. Each phase contributed to the successful implementation of the project and ensured the delivery of a reliable helpdesk platform.  
Project Development Phases  
1. Requirement Analysis  
The first phase involved understanding the query-resolution process and identifying the challenges associated with manual query handling. Functional and non-functional requirements were gathered to define the scope of the application and determine the technologies required for development.  
2. System Design  
Based on the gathered requirements, the overall system architecture, database schema, API structure, and user interface were designed. This phase established the interaction between staff members, the AI engine, and the database.  
3. Development  
The application was developed using FastAPI for the backend and HTML, CSS, and JavaScript for the frontend. PostgreSQL was used as the primary database, while SQLite served as a fallback database during offline development.  
4. AI Model Integration  
Artificial Intelligence and Natural Language Processing (NLP) techniques were integrated to automate query analysis. Sentence Transformers were used to measure semantic similarity between student queries and FAQ entries, while TF-IDF was used for keyword-based matching. Student roll number and department were extracted using regular expressions.  
5. Testing  
The application underwent functional and integration testing to verify the correctness of APIs, authentication, query processing, response ranking, and dashboard functionalities. Errors identified during testing were resolved to improve system reliability.

3.4 Problem Statement  
The following challenges in the traditional helpdesk support process motivated the development of CampusBot:  
1. Time-Consuming Manual Query Handling  
Staff often receive hundreds of student queries for a single support ticket. Manually reviewing each query is slow, repetitive, and delays the query-resolution process, making it difficult to identify suitable queries efficiently.  
2. Inaccurate Query Matching  
Traditional helpdesk support mainly relies on manual keyword searching, which may overlook matched queries whose student queries use different terminology. This results in inaccurate response matching and reduced response quality.  
3. Human Bias and Inconsistent Evaluation  
Manual response evaluation is influenced by personal judgment and unconscious bias, leading to inconsistent response decisions. Factors such as age, gender, or query format may unintentionally affect response selection.  
4. Lack of Intelligent Helpdesk Support Analytics  
Many existing helpdesk support systems do not provide AI-driven insights, response ranking, or visual analytics. Staff lack objective decision-support tools to compare queries effectively and make data-driven response decisions.

D. System Design  
1. Architecture Overview  
The CampusBot application follows a three-tier client-server architecture, consisting of the Presentation Layer, Application Layer, and Database Layer.  
Presentation Layer (Frontend)  
Developed using HTML5, CSS3, and JavaScript, the frontend provides an intuitive interface where staff members can register, log in, submit queries, create FAQ entries, evaluate queries, and view query analytics.  
Application Layer (Backend)  
The backend is implemented using FastAPI (Python). It handles user authentication, query processing, AI-based query matching, similarity score calculation, business logic, and communication with the database.  
Database Layer  
The system stores staff member information, query details, student queries, FAQ entries, evaluation scores, and query history in PostgreSQL (Supabase Cloud). SQLite serves as a backup database whenever the cloud database is unavailable.

6. API Calls  
The application provides a RESTful interface secured by OAuth2 and JSON Web Tokens (JWT).  
1. Authentication Portal  
POST /api/auth/register  
Description: Registers a new system user and automatically binds them to an organization.  
Request Body (JSON):  
{  
  "email": "user@company.com",  
  "password": "Password123",  
  "full_name": "Priya Sharma",  
  "role": "Student",  
  "organization_name": "College Helpdesk"  
}  
Response (JSON): Returns JWT bearer token payload.  
POST /api/auth/login  
Description: Authenticates user credentials.  
Request Body (Form Data):  
username: user email  
password: password string  
Response (JSON): Returns access token and role bindings.  
Error Handling: Returns 400 Bad Request with "Email is not registered." or "Incorrect password." for precise troubleshooting.  
GET /api/auth/me  
Description: Returns current authenticated user profile information.  
Headers: Authorization: Bearer <token>  
Response (JSON): User model record.  
2. Query Ingestion & NLP Pipeline  
POST /api/chat/query  
Description: Accepts a student query, runs it through the NLP intent-matching pipeline, and returns the best-matching FAQ response.  • Headers: Authorization: Bearer <token>  
Request Body (Multipart Form):  
query (String): Raw student question text.  
attachment (File, optional): Supporting file such as a screenshot or form (PDF, DOCX, image).  
Response (JSON): Returns matched faq_id, confidence score, and response text.

The system can be extended to accept spoken queries by converting speech to text using speechrecognition models, enabling hands-free interaction. This would make the chatbot more accessible to a wider range of students.  
2. Multilingual Query Support  
Future versions can understand queries written in regional languages such as Hindi, using advanced multilingual NLP models. This will make the chatbot accessible to a wider range of students across different regions.

The application can be deployed on cloud platforms such as AWS, Microsoft Azure, or Google Cloud Platform with containerization using Docker and Kubernetes to support large-scale helpdesk activities.  
6. Email and Notification System  
Automatic email or SMS notifications can be integrated to inform students about ticket status updates, scheduled maintenance, and helpdesk announcements, improving communication between staff and students.  
7. Mobile Application  
A dedicated Android and iOS application can be developed to allow staff to manage FAQ content and monitor query analytics directly from mobile devices.  
8. Predictive Query Analytics  
Future versions can include predictive analytics to estimate peak query periods, common problem areas, and student-satisfaction trends using historical helpdesk data.  
  
5.1 Conclusion  
The CampusBot – AI-Powered College Helpdesk Chatbot was successfully designed, developed, and implemented to automate the query handling and response evaluation process. The project effectively utilizes Artificial Intelligence (AI) and Natural Language Processing (NLP) techniques to analyze student queries, compare them with FAQ entries, and rank queries based on their suitability.  
The integration of Sentence Transformers, TF-IDF, FastAPI, and PostgreSQL enabled the development of a secure, efficient, and intelligent helpdesk platform. The system significantly reduces the time and effort required for manual query handling while improving the accuracy, consistency, and fairness of response selection. Features such as secure authentication, rolebased access control, query processing, AI-powered matching, response ranking, and interactive dashboards enhance the overall helpdesk experience.  
The project also provided valuable practical experience in applying AI technologies to solve realworld helpdesk-support challenges. It strengthened knowledge of machine learning, NLP, web application development, database management, API development, and software engineering practices.  
In conclusion, CampusBot demonstrates how Artificial Intelligence can transform traditional helpdesk support into a faster, more accurate, and data-driven process. With future enhancements such as AI-based interview analysis, multilingual support, cloud deployment, and predictive analytics, the system has the potential to evolve into a comprehensive intelligent helpdesk platform for organizations of all sizes.
